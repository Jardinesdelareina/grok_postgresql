# Синхронная репликация

RPO (Recovery Point Objective) - целевая точка восстановления, то есть максимально допустимый объём данных, который мы готовы потерять при аварии, выраженный во времени.

### Режим 1: async (по умолчанию, RPO > 0)

* запись не ждёт реплик

* при failover можно потерять последние транзакции

* максимальная доступность

* когда: логи, метрики, кэш, некритичные данные

```
synchronous_mode: off
synchronous_mode_strict: false
```

### Режим 2: sync + деградация в async (RPO=0 в норме, RPO > 0 в окне без sync)

* Patroni выбирает ОДНУ sync-реплику

* коммит ждёт подтверждения от неё

* sync-реплика упала - Patroni переключает на другую или деградирует в async

* запись не блокируется

* когда: большинство SaaS/веб, баланс надёжности и доступности

```
synchronous_mode: on
synchronous_mode_strict: false
```

### Режим 3: STRICT (RPO = 0 всегда, но простой при падении sync)

* как режим 2, но если sync-реплики нет - запись блокируется
* лучше простой, чем потеря данных
* когда: финансы, биллинг, аудит - потеря данных недопустима
    
```
synchronous_mode: on
synchronous_mode_strict: true
```
